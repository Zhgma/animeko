# 播放与阅读记录

播放记录页提供番剧、漫画、小说三个分类。番剧沿用 `EpisodePlayHistoryRepository` 的本地数据库和删除队列；漫画、小说通过 `ReadingHistoryStore` 在 Preferences 中保存每个作品、来源和书籍的最近阅读位置，最多保留 200 本。多个本地小说共用 `subjectId = 0`，用来源及书籍 ID 区分。

“同步到 Animeko 服务端”仅控制番剧播放记录的上传和下载。`playback.history.cloudSyncEnabled` 缺省为 `false`，包括旧版本升级后没有该设置的情况。`PlaybackHistorySyncer.syncOnce` 检查此设置，登录、后台保存和手动刷新共用该入口。开启后触发一次同步；关闭后继续保留本地记录和待同步操作，下次开启时同步这些操作。已发出的请求无法撤回，关闭后收到的结果不应用到本地。收藏及“看过”状态使用独立同步逻辑，不受此开关影响。

漫画、小说记录不发送到番剧播放记录 API。漫画保存章节、页码和总页数；小说保存书源、目录、章节、段落索引和段内偏移。点击记录时先恢复原来源及位置，再创建详情页和阅读器。漫画恢复位置时保留当前的左右顺序、首张单独显示等布局设置。

首次读取列表时从 `manga.reader.*` 和 `novel.position.*` / `novel.reader.*` 迁移已有阅读位置。旧记录没有时间戳，界面显示“历史阅读位置”。迁移标记与结果原子保存，删除记录后不会再次由旧位置生成；实际重新阅读后可以生成记录。删除仅移除历史列表中的条目，保留收藏、缓存和原阅读位置。

小说阅读位置保存 `coverUrl`，详情加载后补充封面。历史列表通过原有 Bangumi 书籍通道补齐有条目 ID 的缺失封面；同一条目的多条来源记录共用已有封面。补充封面不修改阅读时间、排序或进度，也不恢复已删除记录。单次页面会话对每个缺失条目请求一次，网络失败保留列表，下次打开时重试；本地文件不使用书名猜测 Bangumi 条目。

`PlaybackHistoryConsentTest` 验证默认关闭、登录及手动刷新不能绕过开关、开启后同步和再次关闭后保留本地队列；`ReadingHistoryStoreTest` 验证迁移、去重、删除及来源与位置恢复；`ReadingHistoryContentTest` 验证分类、开关和续读 / 删除操作。
