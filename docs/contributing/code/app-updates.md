# 应用更新检查

`UpdateChecker` 通过应用的 `ScopedHttpClient` 查询本仓库的 GitHub Releases。API 不可用时读取同仓库公开发布页面，并从实际的附件列表提取下载地址。两条路径共用代理、版本比较、发布渠道和安装包匹配规则；Android 正式、调试与 TV 包不互相替代。

API 返回 403 或 429 时，当前检查器根据 `Retry-After` / `X-RateLimit-Reset` 暂停 API 请求，缺少这些头时等待一小时；等待期间检查公开发布页面。取消检查会传播取消信号。公开页面访问失败、内容无法识别或分页超过上限时报告检查失败，不将失败显示为没有更新。公开页面最多读取 50 页，只为比当前版本新且符合渠道的发布读取附件。

`UpdateCheckerProxyTest` 覆盖 API 限流及恢复时间、正常 API 请求、公开页面分页、发布渠道、Android 包隔离、下载地址来源、取消以及备用页面失败。`ForkUpdateTest` 覆盖版本和安装包选择。

## 下载进度和后台通知

手机与桌面应用由 `AniApp` 提供同一份 `AppUpdateViewModel`，`AniAppContent` 展示全局更新窗口。主页和设置页共用下载状态，切换页面不创建另一份下载任务。窗口支持后台收起、完成或失败时展开，以及通过 `UpdateDownloadUiRequests` 重复展开。

Android 的 `UpdateDownloadService` 在更新下载期间使用 `dataSync` 前台服务，通知显示百分比，传输完成但尚未校验成功时显示校验状态。通知点击通过不可变的 Activity PendingIntent 将应用带到前台并展开当前下载，用户仍可再次收起。完成、失败会结束前台服务并保留可点击的结果通知；取消或安装会移除通知。服务不自动重启已丢失的内存任务，系统超时会结束下载并提示重试。

通知状态由 ViewModel 的后台作用域持续收集，独立于界面的可见生命周期。后台按钮请求通知权限；通知被禁用时保留可见进度并提示开启权限，避免将任务隐藏到无法查看的位置。
